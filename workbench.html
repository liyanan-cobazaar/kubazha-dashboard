一、核心计算规则
规则公式示例
完成率完成率 = 实际值 ÷ 目标值实际100 / 目标200 → 50%
流量增长目标基期流量 × 1.15（同比增长 15%）基期100 → 目标115
流量完成率当月实际流量 ÷（基期流量 × 1.15）实际120 / 115 → 104%
保底机制完成率 < 30% 时按 30% 计算实际10% → 记30%
封顶机制单项得分 ≤ 权重 × 120%权重10 → 上限12
单项得分单项得分 = 完成率 × 权重104% × 权重10 → 10.4
结算完成率以上月结算率 85% 为目标，完成率 = 结算率 ÷ 85%结算率90% → 106%
未对接财务结算率结算率标注「未对接财务」的项目统一按保底完成率 30% 计入平均，不做酌情调整（2026-09-05 定稿）专员单项目未对接 → 10分×30% = 3分；营销负责人 → 15分×30% = 4.5分
二、基期选择规则（重要）
场景规则示例
有同期数据优先使用去年同期流量作为基期去年同月100 → 基期100
无同期数据或同期为 0使用上月流量作为基期（环比）上月80 → 基期80
新项目按环比计算首月无同期 → 取上月
流量增量：每个项目按「实际订单金额 − 基期流量」计算；区域负责人的增量 = 其区域内所有项目增量之和；区域评分①的基期 = 区域内各项目基期之和（每项目同期为 0/缺失时同样用上月流量，逐项目回退）。

区域主管「校园行/培训/用户池/触达」口径（2026-09-02 调整为总量口径）：完成率 = 区域内各运营专员、项目负责人及主管本人直管项目的实际值合计 ÷（人均目标 × 区域人数）；先算出完成率，再做保底30%/封顶120%，最后 × 权重。例：区域6人共培训14场，人均目标4场 → 14÷(4×6)=58.3%。
区域主管「结算率」口径：区域内所有项目的算术平均结算率 ÷ 85%，先算出完成率，再做保底30%/封顶120%。「未对接财务」项目同样计入平均：按保底完成率 30%（等效结算率 85%×30%=25.5%）计算（2026-09-04 调整，此前未对接项目不计入）。
「未对接财务」结算率保底计分规则（2026-09-05 定稿）：项目尚未对接财务的，当月统一按结算率权重的 30% 保底计分（运营专员 10 分制 → 每个未对接项目 3 分、营销负责人 15 分制 → 4.5 分），不再提供酌情调整，规则统一透明、避免人为争议。项目财务对接落地后，结算率恢复正常数值计算。
注意：区域主管主观项中的「培训场次」特指「团队培训 / 内部会议」（③，8分），与客观项「培训」（按区域总量完成率，7分）口径不同。
人员名单口径：王春光、张亚娟是两个人，不存在「王春光/张亚娟」此人。两人共同负责清华大学项目——王春光的绩效按清华大学项目数据计算；张亚娟的绩效中清华大学为其项目之一（连同本人其他项目合并计算）。导入表格中再出现「王春光/张亚娟」写法的，系统自动按「王春光」归一处理。

五、绩效确认与申诉流程（闭环管理）
环节说明时限
① 结果确认被考评人（区域主管 / 营销负责人 / 运营专员）在本人绩效页阅读结果及评分依据（含计算过程）后，勾选确认声明并提交。前置条件：评分须先完成——管理员给区域主管评完主观分、区域主管给本区域运营专员/营销负责人评完主观分后，被评分本人的确认与申诉入口才会开放；评分未完成前无法确认或申诉评分送达后 3 个工作日内
② 提出申诉对结果有异议的，勾选异议指标、填写理由及依据后提交申诉（在确认区点「对结果有异议」）。管理员裁决前，申诉人可随时撤销申诉：撤销后回到「待确认」状态，可重新确认或再次申诉，撤销操作及原申诉内容全程留痕同上，3 个工作日内
③ 区域负责人初审区域负责人在「确认与申诉」页顶部的申诉待办处理区（或员工绩效卡内）选择「审核通过（转管理员复核）」或「驳回申诉」，并填写理由。区域负责人驳回不直接终结申诉——员工申诉权不由区域负责人单方面终结，驳回后连同理由转管理员终裁2 个工作日内
④ 管理员（运营总监）复核最终裁决：结果维持不变 或 结果已更新（调整结果）；裁决意见全程留痕。裁决为「结果已更新」时，系统自动记录调整前分值，申诉人本人、该员工的区域负责人、管理员均可查看调整前后各项分值对比（含各指标明细与变化）。裁决有误需补充材料时，管理员可在「确认与申诉」页展开记录，撤销裁决退回「待管理员复核」重新裁决（原裁决留痕）；如需整个流程作废重来，可执行重置确认流程（超级权限）回到「待确认」状态，全部历史留痕、员工可见流程曾被重置3 个工作日内
状态查看：申诉处理进度全程可查——员工绩效卡与「我的历史确认记录」中实时显示「待主观评分 / 待本人确认 / 申诉中 · 待××初审 / 待管理员复核 / 结果已更新（或结果维持不变）」；区域负责人、管理员在「确认与申诉」页集中查看待办与全部历史档案。
调整前后对比：管理员裁决为「结果已更新」时，系统自动记录调整前分值；申诉人本人、该员工的区域负责人、管理员均可在绩效卡申诉详情区、确认台账（关键节点列与展开时间线）、本人历史记录中查看调整前后各项分值对比（同区域其他专员/营销负责人不可见）。
确认与申诉效力：逾期未确认且未提出申诉的，视为对当月考核结果无异议。申诉期间当月考核结果暂按原结果执行；裁决后如需调整，差额随最近一次工资发放补足或核减。确认记录（姓名、时间、当月考核版本）由系统自动留存。
评分顺序与确认门槛：先由管理员完成区域主管的主观评分，再由区域主管完成本区域运营专员/营销负责人的主观评分；两级评分均完成后，被评分本人方可确认结果或提出申诉，3 个工作日确认期自本人评分送达后起算。
跨区域人员双评（仅郭旺）：郭旺项目横跨东北西北、天津两个区域，其主观分由两位区域负责人（高欢庆、刘金玲）各自填写，二人均提交后按平均值计分；任一人未填写视为评分未完成，郭旺暂不能确认或申诉（自2026年8月起执行，此前月份按原单人评分口径）。
六、用户池与触达口径
1. 用户池建档：以采购人为最小单元建档，信息链：学校 → 学院 → 实验室/课题组 → 采购人。同一采购人服务多个课题组/实验室的，多个课题组填在同一格（顿号分隔），只建一个档案，不重复建档。
建档去重：同一采购人 + 同一学校 + 同一学院只算 1 条（同一采购人在同校不同学院算不同用户）；补录信息、变更等不计新增；同一人当月重复录入只计 1 次。
建档必填项填写要求
采购用户（模板第1列）采购人真实姓名，即建档主名（原「姓名」列已并入此列）
学校 / 学院 / 实验室/课题组完整填写；多个课题组填同一格，顿号分隔
联系方式手机 / 微信 / 邮箱至少填一项
用户角色PI/课题组负责人 / 采购老师 / 实验员 / 采购秘书 / 研究生 / 其他
首次建档（原“新增日期”）年-月-日（如 2026-08-20）
用户基本信息（选填）职称/头衔、研究方向、采购习惯、重要备注等补充信息，自由填写；导入后显示在学校用户列表「用户基本信息」列
走访人归属运营人员（用户池这里统称走访人，对应月度数据维护和绩效里的运营人员）
2. 用户池（绩效口径，2026-09 起自动统计）：绩效中的「用户池」人数由系统按本表格自动统计，月度数据里无需再手填（该列可不填，填了也不导入）。当月用户池数 = 新增建档数 + 完整回访数： ① 新增建档 = 首次建档日期在该月、且 A–M 列信息完整的记录（「用户基本信息」为选填列，不计入完整性判定；下单金额需填写，填 0 也算完整，留空算不完整）； ② 完整回访 = 「回访时间 + 回访类型 + 回访内容」三项齐全的一组，按回访时间归属月份，每组计 1（不完整的组不计）。 同一人当月既有新建档又有回访，两项各计各的；特殊情况可由管理员在「数据维护」中修正（修正值优先于自动统计，留空即恢复自动）。2026-09 之前的历史月份仍按原手填值。明细可在用户池CRM「月度用户池动态」中按走访人逐月查看。
3. 回访：回访是用户池的持续运营动作。每次回访在用户池表格末尾追加一组「回访时间N / 回访N类型 / 回访N内容」（N 按顺序递增，几次回访填几组）；回访类型沿用 8 类：首次拜访、常规走访、深度回访、问题处理、需求发掘、新品推介、售后跟进、其他。回访自动更新档案（最近触达 = 日期最大那次回访，无需也不可手填；走访类型 / 走访内容自动取最新一组），每组完整回访计入当月用户池数（见第 2 条），但不计触达。
渠道留痕要求触达计数规则
电话通话记录或 CRM 日志每通有记录的通话计 1 次
微信 / 企微聊天记录截图或 CRM 备注每次主动沟通计 1 次
站内信 / 短信平台后台发送记录每次发送计 1 次
培训现场培训活动记录按实际沟通人数计，一人 1 次（不按场次）
校园行现场校园行活动记录按实际沟通人数计，一人 1 次（不按场次）
线下走访 / 回访回访列组记录不直接计触达，仅下面两种情况计：①走访中为老用户首次加到微信/拿到手机号等新联系方式，计 1 次（同一用户仅计一次）；②新用户在现场扫码登记、发 DM 单、留联系方式，计 1 次（通常同时建档为用户池新增）
4. 触达：通过可追溯渠道向用户传递一次明确信息并留痕，计 1 次（渠道与留痕见上表）。例行回访、已有联系方式的日常走访，不计触达——触达看的是有没有新增一个可联系的连接，不是有没有见面。
5. 去重：同一用户同一天同一渠道多次触达合并计 1 次；不同渠道可分别计；同一活动内与同一人的多次互动合并计 1 次；为同一用户新增联系方式只计 1 次（首次加微信后，后续再补邮箱等不重复计）。
主观分云端共享：区域主管填本区域下属，总部可改所有人；填完自动同步全员可见。管理员可导出/导入备份。
